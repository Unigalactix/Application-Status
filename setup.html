Overview/ Setup guide

From spreadsheet to workspace

Your tracker. Your data.

A step-by-step guide to fork this project and publish your own application dashboard. No backend, API key, or build step required.

You will need a Google account, a GitHub account, and a public repository for the simplest free GitHub Pages setup. Allow about 20–30 minutes.

Before you publish: your data will be public

Published Google Sheets and GitHub Pages are not private storage. Anyone with a published URL may read every exported cell, even if the dashboard hides it.

  • Create separate, sanitized public tabs. Keep personal notes, recruiter emails, private email links, and sensitive compensation details in a private sheet.
  • Never put passwords, access tokens, or API keys in the repository or sheet.
  • Forking initially copies this demo's source URLs. Replace both feed URLs before enabling Pages.

Step 01

Create your application tracker

  1. Open a new Google Sheet and name it Application Tracker.
  2. Create a tab called Public Applications. Put the following header row in row 1. Copy the CSV line into A1, then use Data → Split text to columns → Comma if Sheets does not split it automatically.
Company,Role / Title,Application ID,Current Status,Application Date,Last Status Update,Recruiter / POC (Name & Email),Resume Version,Interview Stage,Salary Band,Referral,Location / Work Mode,Portal / Source,Action Required / Next Steps,Follow-Up Due Date,Follow-Up Status,Last Follow-Up Date,Rejection Stage,Notes / Verification Evidence,Latest Email Link
  1. Add one row per application. Start with Company, Role / Title, Current Status, and Application Date. Use YYYY-MM-DD for dates. Leave unavailable information blank instead of inventing it.
  2. Use statuses such as Under Review, Action Required, Declined, Inactive / Closed, or Offer.
  3. Use stage labels such as Application Submitted, Recruiter Screen, Technical Assessment, or Final Interview. Outreach is not a confirmed appointment. Closed/offer outcomes take precedence over an earlier interview stage.
  4. Use a unique Application ID where available. Duplicate non-placeholder IDs are merged using the newest status update and earliest application date. Rows without an ID remain separate.
  5. Set Follow-Up Due Date to override inferred cadence. Record Last Follow-Up Date in the sheet if completions should be shared across devices.

Optional Rejection Stage categories: Before screening, After assessment, After interview, Position closed, or Unknown. Without these, the dashboard labels its category as inferred.

Step 02

Create a job-posting feed

Create another sanitized spreadsheet or tab named Public Jobs, with this header row:

Job Title,Company,Location,Date Posted,Work Type,Estimated Compensation,Match Score,Matching Skills / Resume Alignment,Referral Contact (Name / Role),Application Link
  • Add jobs you want to consider. Match Score is a 0–100 value you provide; this site does not calculate AI matching or scrape job boards.
  • Application Link must display the full https://... application URL. Do not use a hyperlink label like "Apply Here"; published CSV may lose the underlying destination.
  • If you do not want a job feed yet, publish a header-only jobs tab. The dashboard will show a valid empty state rather than someone else's jobs.

Step 03

Publish each sanitized tab as CSV

  1. In Google Sheets, choose File → Share → Publish to web.
  2. Select only the intended public tab, not the entire workbook. Choose Comma-separated values (.csv).
  3. Select Publish, confirm, and copy the published CSV URL. Repeat for the jobs tab.
  4. Open each link in a private/incognito window. Confirm it downloads or displays CSV without a sign-in prompt and contains only safe public data.
  5. Keep automatic republishing enabled if you want sheet edits to become available. Google may take time to republish changes.

A published CSV URL usually resembles:

https://docs.google.com/spreadsheets/d/e/YOUR_PUBLISHED_ID/pub?gid=YOUR_TAB_ID&single=true&output=csv

The normal spreadsheet sharing URL and /pubhtml embed URL are not CSV endpoints. Do not discard gid when publishing two tabs in one workbook; it selects the correct tab.

For a public viewing shortcut, publish the same tab as a web page and copy its /pubhtml link. Keep the tab's gid parameter where applicable.

Step 04

Fork this repository

  1. Create a GitHub account or sign in.
  2. Open Fork Application-Status.
  3. Choose your account as owner, keep the name Application-Status or choose your own, and create the fork.
  4. Work in your fork for the remaining steps. Do not edit or deploy the original repository.

Step 05

Connect your sheets and personalize

  1. In your fork, open app.js, select the pencil (Edit), and find DATA_SOURCE. Replace its url with your application CSV URL.
  2. Find JOBS_SOURCE. Replace url with your jobs CSV URL and sheetUrl with the matching public jobs web-page link.
  3. In index.html, replace the footer's published Google Sheet link with your tracker web-page URL. Update the footer GitHub link to your fork.
  4. In setup.html, update the repository/fork links if you want the guide to direct future users to your fork rather than the original project.
  5. Optionally change WEEKLY_APPLICATION_GOAL in app.js. SCHEDULED_UPDATE_HOURS only describes an estimated external schedule; it does not automate sheet updates.
  6. Commit each edit to your fork's main branch. Keep the JavaScript strings quoted and use raw & characters in JavaScript URLs, not HTML's &amp; escape.
const DATA_SOURCE = {
  label: "Live sheet",
  url: "YOUR_APPLICATIONS_PUBLISHED_CSV_URL"
};

const JOBS_SOURCE = {
  label: "Job postings feed",
  url: "YOUR_JOBS_PUBLISHED_CSV_URL",
  sheetUrl: "YOUR_JOBS_PUBLISHED_WEB_PAGE_URL"
};

Keep index.html, app.js, workspace.js, styles.css, workspace.css, setup.html, and favicon.svg in the repository root. No npm installation or build command is needed.

Step 06

Deploy with GitHub Pages

  1. In your fork, open Settings → Pages.
  2. Under Build and deployment, choose Deploy from a branch.
  3. Select main and / (root), then select Save.
  4. Wait for the Pages deployment to complete. Check your repository's Actions tab if it is still pending or fails.
  5. Return to Settings → Pages and open the published site link. A project site usually looks like the URL below; use your actual username and repository name, including case.
https://YOUR_USERNAME.github.io/YOUR_REPOSITORY/

Step 07

Verify before sharing

  • Both feed indicators show a successful fetch, and the companies belong to your own sheets.
  • The Total applications count matches your unique application IDs, not necessarily the number of sheet rows.
  • Open every KPI page. Check the Total applications calendar and select a date with known entries.
  • Test a follow-up, a star, a saved view, and a reload. These actions stay in that browser, not in your Google Sheet.
  • Check the layout on a phone and in both themes. Open Setup guide from the footer.
  • Try adding a harmless test row in your public sheet, wait for republishing, then select Refresh data. Remove the test row afterward.
  • Review the published CSV once more for private information before sharing the website.

Keep it working

  • Where do updates happen? Edit Google Sheets; the site reads it on page load or manual refresh. This project does not read your email, scrape jobs, schedule interviews, or write back to Sheets.
  • Feed unavailable? Test its CSV URL in a private window, verify the correct tab is published, and check required headers. One failed feed does not block the other.
  • Old data? Allow Google time to republish. Fetched-at time and latest sheet activity are different; the estimated 8 AM / 8 PM schedule does not prove an upstream update.
  • Apply link unavailable? Use a raw absolute HTTP(S) URL in the cell's displayed value, not a formula label.
  • Unexpected counts? Check applied-date range, saved/list filters, closed statuses, and duplicate IDs. Missing compensation or resume data is reported as missing.
  • Browser data missing? Local stars, follow-ups, saved views, and change comparisons do not follow you to another device or private window. Add shared follow-up completions to Last Follow-Up Date in the sheet.
  • Pages is 404? Verify the main/root publishing setting and deployment status. Confirm index.html is in the root and the URL uses your repository name.
  • Need to stop publishing? Disable Pages in repository settings and stop publishing each Google Sheet tab. Disabling the website alone does not unpublish a sheet.

Optional local preview

Clone your fork, open a terminal in its folder, and run:

python -m http.server 8000

Open http://localhost:8000. A local HTTP server is needed; do not open index.html as a file. Stop the server with Ctrl+C when finished.
